# OpenDuck Mini 中试平台测试操作文档

**版本：** V2.2  
**日期：** 2026-07-30  
**适用对象：** 飞特 STS3215 单舵机、组装后的左腿/右腿/头部及完整 OpenDuck Mini  
**本文只说明如何测试，不说明代码实现。**

## 1. 测试前准备

### 1.1 所需设备

- 一台 Windows 电脑；
- 一台已安装 OpenDuck Mini 项目的树莓派 Zero 2W；
- OpenDuck Mini 电机驱动板；
- 待测 STS3215 舵机、组装部件或完整机器人；
- 舵机供电和连接线；
- 可以让 Windows 电脑与树莓派接入同一网络的路由器或热点。

### 1.2 接线

```text
Windows电脑 ──同一局域网── 树莓派
                           │
                           └──排线── 电机驱动板 ──串联总线── STS3215
```

测试前确认：

1. 树莓派与电机驱动板之间的排线已插紧；
2. 舵机电源、通信线方向正确；
3. 舵机指示灯正常；
4. 测试部件已悬空或可靠固定；
5. 关节在测试方向至少有足够活动空间；
6. 周围没有人员、线缆或物体阻挡。

舵机亮灯只能说明已经供电，不能证明树莓派已经识别驱动板或能够读取舵机。

## 2. 将电脑和树莓派连入同一局域网

Windows 电脑和树莓派必须连接同一个路由器或同一个手机热点。

已知树莓派 IP 时，可直接连接。IP 不确定时，可在树莓派本地终端执行：

```bash
# 查看树莓派当前局域网IP地址
hostname -I
```

例如显示 `192.168.0.106`，则该地址就是本次 SSH 和网页访问使用的 IP。树莓派重新连接网络后 IP 可能变化，应以实际显示为准。

## 3. 从 Windows 登录树莓派

在 Windows 打开 PowerShell 或 Windows Terminal：

```powershell
# 通过SSH登录树莓派；请把IP替换为树莓派当前实际地址
ssh duck@192.168.0.106
```

第一次连接若出现主机指纹确认，输入：

```text
yes
```

随后输入密码：

```text
1
```

密码输入时终端不会显示星号或字符，直接输入后按 Enter 即可。

登录成功后，提示符应类似：

```text
duck@raspberrypi:~ $
```

## 4. 准备测试环境

每次新开一个 SSH 终端，都必须重新进入项目并激活虚拟环境：

```bash
# 进入OpenDuck Mini项目目录
cd /home/duck/open_duck_mini_runtime

# 激活包含rustypot和ONNX依赖的虚拟环境
source ~/.venv/bin/activate
```

激活成功后，提示符前会出现：

```text
(.venv) duck@raspberrypi:~/open_duck_mini_runtime $
```

`source ~/.venv/bin/activate`在同一个 SSH 终端中只需要执行一次；新开终端后要重新执行。

### 4.1 检查驱动板是否被树莓派识别

```bash
# 检查固定通信设备/dev/ttyACM0是否存在
ls -l /dev/ttyACM0
```

正常时会显示 `/dev/ttyACM0`设备信息。若显示：

```text
No such file or directory
```

说明树莓派尚未识别电机驱动板，暂时不要运行舵机动作测试。先检查排线、USB连接、驱动板供电和接口方向。

可继续执行：

```bash
# 查看树莓派当前识别到的USB设备
lsusb

# 查看最近的USB和串口内核日志
dmesg --ctime | tail -n 30
```

三个测试脚本都使用 `/dev/ttyACM0`和 `1,000,000 bit/s`，正常运行时不需要输入串口或波特率。

## 5. 打开实时网页的方法

运行测试脚本后，终端会打印类似地址：

```text
实时曲线：http://192.168.0.106:8765/
请在与树莓派同一局域网的电脑浏览器中打开该地址
```

在 Windows Terminal 或支持链接识别的终端中：

1. 按住键盘 `Ctrl`；
2. 用鼠标左键单击终端里的 `http://...`地址；
3. 浏览器会打开实时波形页面。

如果 Ctrl+单击没有反应：

1. 用鼠标选中完整网址；
2. 复制网址；
3. 粘贴到 Edge 或 Chrome 地址栏；
4. 按 Enter 打开。

树莓派 2W 不需要打开浏览器。网页在 Windows 电脑上查看。测试脚本运行期间不要关闭 SSH 终端。

若 `8765`端口已被占用，程序会自动使用 `8766`、`8767`等后续端口。必须打开终端实际打印的地址，不能固定只输入8765。

## 6. 三种测试的选择

| 检测对象 | 运行脚本 | 允许继续的ID条件 |
|---|---|---|
| 单个新舵机 | `sts3215_pilot_test.py` | 只识别到1个项目舵机 |
| 左腿、右腿或头部 | `sts3215_module_test.py` | 当前组件的ID全部在线 |
| 完整机器人 | `pilot_test_platform.py` | 14个指定ID全部在线 |

右腿为 `10–14`，左腿为 `20–24`，头部为 `30–33`。

## 7. 测试一：单舵机

### 7.1 接线要求

驱动板总线上只连接一个待测 STS3215。不要同时连接多个舵机。

待测舵机输出轴必须没有机械阻挡。单舵机默认测试幅度较大，不应在已装入腿部或头部机构后使用该脚本。

### 7.2 先做只读扫描

```bash
# 只扫描唯一舵机，不写PID且不发送动作
python scripts/sts3215_pilot_test.py --scan-only
```

正常结果应显示一个已识别 ID。若识别到多个 ID，应断开其他舵机后重新扫描。

### 7.3 执行动作测试

```bash
# 自动扫描唯一舵机、写入项目测试PID并执行波形测试
python scripts/sts3215_pilot_test.py
```

程序会：

1. 自动识别唯一 ID；
2. 显示测试前舵机原始 PID；
3. 根据 ID 写入腿部或头颈测试参数；
4. 打印实时网页地址；
5. 等待操作者打开网页并按 Enter；
6. 执行平滑位置波形；
7. 输出 PASS 或 FAIL；
8. 在网页提供 CSV、JSON 和中文 HTML。

测试过程中观察舵机是否平滑运动。出现异响、机械碰撞或线缆缠绕时立即按 `Ctrl+C`停止。

## 8. 测试二：组装好的左腿、右腿或头部

### 8.1 接线要求

每次只连接一个完整组件：

| 组件 | 必须在线的ID |
|---|---|
| 右腿 | 10、11、12、13、14 |
| 左腿 | 20、21、22、23、24 |
| 头部 | 30、31、32、33 |

程序会自动识别组件，不需要输入组件名称或 ID。

### 8.2 先做只读扫描

```bash
# 自动识别当前组件并列出已识别ID和缺失ID
python scripts/sts3215_module_test.py --scan-only
```

确认终端输出：

```text
识别组件：左腿、右腿或头部
已识别 ID：[...]
缺失 ID：[]
```

若“缺失 ID”不是空列表，先检查对应舵机供电、串联线和 ID，不要进入动作测试。

### 8.3 执行部件逐关节测试

```bash
# 自动识别当前组件并执行逐关节±15°测试
python scripts/sts3215_module_test.py
```

看到以下安全提示后：

```text
请确认机器人已悬空或可靠支撑，周围无人员和障碍物。
确认后按 Enter 开始动作检测；按 Ctrl+C 取消：
```

检查部件固定可靠，然后直接按 Enter。程序会逐个关节执行：

```text
装配原点 → +15° → 装配原点 → -15° → 装配原点
```

每次只运动一个关节，其他关节保持当前位置。

终端会逐关节打印：

```text
[动作] 正在检测 ID ...
```

实时网页的关节下拉框可切换查看当前和已经完成的关节。

### 8.4 部件装配方向自动判定

项目使用一台人工确认装配正确的整机建立母基准，并自动生成右腿、左腿、头部三个子基准。正常测试部件时不需要输入基准路径：

```bash
# 自动识别组件、自动加载对应方向子基准并执行测试
python scripts/sts3215_module_test.py
```

默认子基准为：

```text
direction_references/right_leg.json
direction_references/left_leg.json
direction_references/head.json
```

保持组件摆放方向、固定方式和供电条件与建立母基准时尽量一致。只有维护或对比其他基准时才使用 `--direction-reference`覆盖默认文件。

报告会分别显示：

- 位置反馈方向：通过或不通过；
- 重力电流方向：通过、反向/不通过、待人工复核、未标定或不适用；
- 基准相似度和判定说明。

髋偏航和头部偏航关节因绕竖直轴运动时重力投影不足，重力电流方向显示“不适用”，只做位置反馈方向判定。没有加载基准时，程序仍完成位置和波形测试，但电流方向显示“未标定”，不会凭电流正负直接判断装反。

## 9. 测试三：完整机器人

### 9.1 进入条件

完整机器人必须识别到：

```text
右腿：10、11、12、13、14
左腿：20、21、22、23、24
头部：30、31、32、33
```

共14个 ID。任一 ID 缺失时，整机动作不会开始。

### 9.2 只扫描整机

```bash
# 只扫描14个舵机，不写PID且不发送动作
python scripts/pilot_test_platform.py all --scan-only
```

确认报告中的“已识别 ID”包含全部14个 ID，并且“缺失 ID”为“无”。

### 9.3 只做整机逐关节测试

机器人应悬空或可靠支撑：

```bash
# 依次对14个关节执行±15°波形测试
python scripts/pilot_test_platform.py assembly
```

逐关节检测全部通过后，终端显示：

```text
测试结论：通过（PASS）
```

### 9.4 只做步态测试

步态测试必须确保机器人不会跌落、撞击人员或拉扯线缆：

```bash
# 使用ONNX模型执行站立、踏步、前进、停止和转向测试
python scripts/pilot_test_platform.py gait
```

### 9.5 依次完成全部整机测试

推荐正式验收使用：

```bash
# 先做14关节检测；全部通过后再自动执行ONNX步态
python scripts/pilot_test_platform.py all
```

若逐关节检测不通过，程序不会继续执行步态。

### 9.6 首次建立整机方向母基准

只可使用一台已经人工确认14个关节装配方向正确的整机建立母基准。机器人必须悬空或可靠支撑：

```bash
# 对正确整机执行逐关节测试，保存母基准并自动拆分三个组件子基准
python scripts/pilot_test_platform.py assembly --save-direction-reference /home/duck/open_duck_mini_runtime/direction_references/robot.json
```

成功后应生成：

```text
direction_references/robot.json
direction_references/right_leg.json
direction_references/left_leg.json
direction_references/head.json
```

后续整机验收不再需要输入基准参数：

```bash
# 自动加载direction_references/robot.json并执行方向及波形检测
python scripts/pilot_test_platform.py assembly
```

位置反馈方向错误，或非偏航关节电流特征与正确基准明确反向时，终端和中文HTML均显示“不通过（FAIL）”及“疑似装配方向错误”，程序返回退出码3。

## 10. 网页曲线怎么看

网页顶部显示当前状态、阶段、采集时间和关节选择框。

### 10.1 原始目标/实际位置图

- 蓝线：程序发送给舵机的输入目标位置；
- 红线：从舵机读取的实际输出位置；
- 横轴：实际测试时间，单位秒；
- 纵轴：位置角度，单位度；
- 蓝线与红线的横向间隔：响应延时；
- 蓝线与红线的纵向间隔：位置误差。

图中蓝色指令点表示输入开始产生有效位移的时刻；红色响应点表示舵机实际输出到达对应响应位置的时刻；双向箭头标注响应延时。

### 10.2 响应时间对齐后的波形

该图把红线按测得的响应延时向左移动，用于观察去除纯时间滞后后，红线与蓝线的幅值和形状是否一致。

原始时序图用于看真实延时，对齐图用于看波形跟随质量。两张图都需要保留。

### 10.3 跟踪误差图

误差定义为：

```text
实际位置 - 输入目标位置
```

误差越接近0越好。换向处出现短时波动不一定立即判为失败，应以报告中的 RMSE、最大绝对误差和安全状态为准。

### 10.4 电流图

用于观察动作过程中的负载变化。关节换向或阻力增大时电流可能上升。持续超过安全阈值时程序会停止测试。

## 11. 测试结果和报告下载

测试完成后，终端和网页顶部都会显著显示：

```text
测试结论：通过（PASS）
```

或：

```text
测试结论：不通过（FAIL）
```

网页顶部会出现下载按钮：

- 单舵机 CSV 原始数据；
- 部件 CSV 原始数据；
- 整机逐关节 CSV；
- 整机步态 CSV；
- JSON 汇总；
- 中文 HTML 报告。

点击下载按钮后，文件保存到 Windows 浏览器的默认下载目录。

必须按以下顺序操作：

1. 先在网页下载需要的文件；
2. 确认 Windows 下载目录中已经存在文件；
3. 再回到 SSH 终端；
4. 按 Enter 关闭网页服务并清理树莓派临时报告。

默认报告位于树莓派 `/tmp/openduck_test_logs/`，按 Enter 后会自动删除。不要先按 Enter 再下载。

确需在树莓派保留报告时：

```bash
# 运行部件测试并在退出后保留树莓派临时报告
python scripts/sts3215_module_test.py --keep-report
```

## 12. PASS/FAIL标准

| 项目 | 通过条件 |
|---|---|
| ID | 当前测试对象要求的ID全部在线 |
| PID | 项目测试PID写入后回读一致 |
| 通信 | 无关键读写超时、无响应、断管或串口失败 |
| RMSE | 每个关节不大于5° |
| 最大绝对误差 | 每个关节不大于15° |
| 位置反馈方向 | 正、负实际位移均至少3°且达到指令幅度20% |
| 非偏航关节装配方向 | 已加载正确基准时，电流特征相似度≥0.65通过；≤-0.65判为疑似反向 |
| 偏航关节装配方向 | 重力电流法不适用，只检查位置反馈方向 |
| 持续大误差 | 不得超过20°并持续0.30 s |
| 电压 | 不低于6.8 V |
| 电流 | 不得超过2.0 A并持续0.50 s |
| 温度 | 70℃以下不提示；超过70℃告警；75℃防损坏紧急断扭矩；不参与方向判定 |

响应延时和等效相位延时是重点记录项，当前不单独决定 PASS/FAIL。

其中，波特率、工作电压范围、运行温度和厂家过流/过热保护边界来自飞特STS3215规格书；6.8V主动欠压、0.50s过流持续时间、RMSE、最大误差、位置方向3°/20%、相似度0.65及当前70℃告警/75℃紧急停机属于OpenDuck项目策略。项目值不是飞特出厂合格标准，后续应根据正确与故意反装样本的批量统计结果调整。

## 13. 常见故障处理

### 13.1 SSH无法连接

检查：

1. Windows和树莓派是否连接同一局域网；
2. 树莓派IP是否变化；
3. SSH命令中的用户名是否为 `duck`；
4. 密码是否为 `1`。

```powershell
# 测试Windows是否能够访问树莓派当前IP
ping 192.168.0.106
```

### 13.2 `/dev/ttyACM0`不存在

这不是舵机ID问题，而是树莓派尚未识别驱动板。

```bash
# 查看固定串口设备是否存在
ls -l /dev/ttyACM0

# 查看USB设备列表
lsusb

# 查看最近USB枚举日志
dmesg --ctime | tail -n 30
```

重新检查树莓派到驱动板的排线、供电、接口方向和数据连接。

### 13.3 显示`Operation timed out`

表示在规定时间内没有收到目标 ID 的有效响应。检查：

- 舵机是否供电；
- 串联通信线是否松动；
- 舵机 ID 是否正确；
- 是否连接了错误的组件；
- 电源是否在动作时压降。

### 13.4 显示`Broken pipe`

表示测试过程中驱动板串口断开、USB重新枚举或底层通信管道失效。即使扫描阶段曾经读取成功，动作阶段仍可能因供电、接触或USB链路不稳定而中断。

停止测试后检查排线、USB连接和供电，再重新确认 `/dev/ttyACM0`。

### 13.5 网页打不开

检查：

1. Windows和树莓派是否仍在同一局域网；
2. 是否打开终端实际打印的IP和端口；
3. 测试脚本是否仍在运行；
4. Windows防火墙是否阻止局域网访问；
5. 是否误把旧IP或固定8765端口作为当前地址。

### 13.6 报告找不到

默认报告存储在树莓派临时目录。若已经在终端按 Enter，临时报告会被删除。正式测试必须先从网页下载，再按 Enter。

[2] 深圳飞特模型有限公司：《[飞特舵机入门教程——以STS3215为例](https://www.feetechrc.com/Data/feetechrc/upload/file/20220618/%E5%85%88%E7%9C%8B%E8%BF%99%E9%87%8C-%E5%85%A5%E6%89%8B%E6%95%99%E7%A8%8B2-1.pdf)》。用于参考舵机ID识别、串联通信、参数设置及调试方法。

[3] Pollen Robotics：《[Rustypot通信库](https://github.com/pollen-robotics/rustypot)》。用于树莓派端STS3215舵机扫描、寄存器读写、目标位置发送和实际状态读取。

[5] OpenDuck Mini运行项目：用于参考树莓派Zero 2W运行环境、舵机硬件接口、关节配置和ONNX步态程序。

**说明：** `RMSE≤5°、最大绝对误差≤15°`为当前OpenDuck Mini中试阶段制定的内部工程验收阈值，用于判断舵机输出是否满足后续装配和步态控制需要，不属于飞特厂家出厂合格标准。后续应结合合格样机及批量测试数据进一步验证和调整。
